## mawork-review 复盘引擎重构（对话式复盘）

**问题诊断**（用户反馈：报告太复杂、太 AI、太多引导分析预测混在里面、缺少反复引导思考）：
旧版是"七步固定流程"，致命缺陷是**第 6 步"引导反问"排在倒数第二步**——初稿已写完才提问，
引导沦为报告末尾的装饰性装饰；同时三层归因表、模式重演表、置信度%、校准系数全塞进正文，
9 月报告 260 行 / 13KB，人不愿读。

**重构为四阶段**：
1. 取数（静默，不刷屏）
2. 抛 3~5 句具体观察 + **2~3 个只有用户能答的问题，然后停下等**
3. **追问至少两轮**（抓最关键一件事往下钻，逼出日期/数量/具体事件名）
4. 用户说"行了写吧"才成文（≤80 行 / ≤5000 字符）

**三种模式**：快问快答（具体问题，不问）/ 对话复盘（默认，必须问两轮）/ 深挖（多轮翻旧账）

**报告硬约束**：不用小节编号；禁止【事实】【判断】【假设】标签、P0/P1/P2、置信度%、校准系数、
模式重演表、三层归因表、"引导反问"章节；表格 ≤2 个；预测不塞进复盘（另开计划文件）；开头即结论。

## 第五轮：因果分析 + 主要矛盾 + 不留情面 + 分层责任

用户四个新要求：①挖主要因果而非关联 ②找主要矛盾和关键问题 ③提问与报告不留情面一针见血 ④多挖历史数据，落地到"人和时代的局限性"。

**新增 `references/causal-analysis.md`（核心资产）**：
- **三层次区分**：相关 / 关联 / 因果。判断标准是**反事实**——拿掉这个原因结果会不一样吗
- **因果五刀**（按序追问）：多重解释 → 反事实（"没做系统那段时间你会做什么"）→ 历史对照（何时开始）→ 找反例（哪次两件事都做到了）→ 分层（能力/意愿/结构）
- **找主要矛盾三维度打分**：影响面 / 逆可控性（解决它几个问题自动消失）/ 反复性。三项都高的那一个就是
- **责任分层**：人（当时知道什么/能力到哪）/ 组织（大参林集权，KA 是乙方）/ 时代（2026 秋招窗口 8-11 月）。**"我没做到"和"我在这位置上也做不到"是两回事**，混淆会导致自责而自责不解决问题
- 假因果反例："没有台账所以投得少" → 台账不会让人想投，真机制是"投了没反馈"

**新增 conversation-guide「一·五、不留情面」**：
- 三角对比：只描述现象（无效）/ 攻击人格（有害）/ **指出机制不评价人（有效）**
- 替换公式：不说"你懒"→"排序从来没被显式决策过"；不说"你该努力"→"这一条是结构问题，努力不解决它"
- 提问锋利度：不用"是不是有点…"软化句式；不接受模糊第一版答案
- **核心一句**：复盘不是为了让用户心里舒服，是为了让下次不再犯同样的错。说得客观点，下次照旧。

**9 月复盘按新标准重写**：主要矛盾定为"秋招投入不足"，其余缺口（#26 大KA、毕设）明确标注为症状或独立议题。
**历史对照挖到的硬证据**：年度计划"多线全开=全线欠账"（三年教训）→ 8 月复盘"秋招持续拖延"→ 9 月**第三次**。
三次都是"发现"而非"改机制"——这是本次归因最锋利的结论。
并加「有些事不是你的问题」一节，明确大参林推不动是位置决定，努力无用。

**描述 vs 分析的区分**（写进底稿）：
- 描述："三套系统把秋招时间吃掉了"
- 分析："排序从未被显式决策过，背后是即时反馈的结构性吸引力 → 解法不是下次重视，是加外部约束"

## 第六轮：方法论与个人数据解耦（架构级修正）

用户提出两个关键质疑：①**这些内容会不会影响 agent 的客观分析**（只是呈现方法还是呈现内容）②**未来提到某个事件或想做某件事都用得上**。诊断后发现两个真实问题，已修正。

**问题一：profile.md 成了"预判答案"**（比预想严重）
原档案有 11 条标为"已确认"的行为模式 + 6 条"事实修正"，等于 agent 还没看数据就有结论。
风险：agent 带"他就是即时反馈偏好"的预设去分析，会把任何事件都解释成这个原因，忽略真正解释。**档案越详细越危险。**

**修正**：
- profile.md 开头加「⚠️ 使用纪律」：明确是**待检验的假设不是结论**
- 正确用法只有三种：提问线索、反例检查、历史对照
- 明确四禁令：❌还没分析就套结论 ❌用旧结论替代当次分析 ❌把新问题往旧模式靠 ❌把 agent 推断当已确认事实
- 章节标题从"行为模式"改为"行为模式（假设，非定论）"
- SKILL 新增「客观性保障」整节，三条禁令 + 理由 + "每次分析都要允许结论被推翻"

**问题二：方法论和案例混在一起**（耦合严重）
统计发现个人化引用：causal-analysis 34 处、profile 45 处、SKILL 19 处、conversation-guide 19 处。
这些文件换个用户/事件就成干扰。

**解耦做法**：全部改为**同等具体的通用示例**（不是删掉案例，是换一个不绑定此人的）

## 第八轮：反事实+反驳工具化 / 历史索引层 / 上下文再压缩

### 1. 反事实与反驳提升为独立工具（conversation-guide 新增「二·五、两个核心工具」）

**反事实问法**——把假设改成"如果"，用来验因果：
| 直接问（套话） | 反事实问（真信息） |
|---|---|
| 这事为什么没做成？ | 如果那三个系统没做，那段时间你会做什么？ |
| 你为什么没投简历？ | 如果不需要做任何系统，你会投多少家？ |
| 这个决策对吗？ | 如果重来一次，你会做同样的选择吗？为什么？ |
**关键用法**：用户给出解释后不要接受，用反事实再问一遍。答案变了说明原解释只是表面说法。
对"伪原因"特别有效——用户说"没时间"，反事实问"如果那件事是今天下午三点的硬截止，你还会做别的吗？"能问出真实排序。

**反驳问法**——主动找对立证据，用来压结论：
"这个项目值得做"→"什么情况会让你放弃它？现在有这个迹象吗？"
"我方向没错"→"如果方向错了，最早的信号会是什么？"
三条规则：必须真的找反例不能敷衍；用户找不到时帮他构造（"如果我只看结果不看过程，我会挑谁？"）；找到反例要认真对待，用户犹豫就是信号。

**分工**：反事实检验因果链，反驳检验结论。**都用在最后一轮（成文前）**。
完整顺序：开放提问 → 追问细节 → 反事实 → 反驳 → 收口。
收口时用反驳收尾："你说该做 A，理由 B，但你刚提到 C 确实存在——如果 C 比 B 更要紧，这选择还成立吗？"
